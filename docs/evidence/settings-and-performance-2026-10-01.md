# 설정 간소화·유휴 성능 측정 — 2026-10-01

## 변경 범위

설정의 중복 제목과 GroupBox를 제거하고, 편집 버튼과 항목 수를 한 줄에 배치했다. 안내 한 줄과 기존 메뉴바 설정·종료·완료 버튼을 유지했다. 편집 상태의 수평 이동 안내와 항목 제거 경고, 권한 요청·오류·취소·다시 접기 경로는 남겼다. 메뉴바 재배치와 복귀 정책은 바꾸지 않았다.

동일한 정상 상태의 AX 창 크기는 **380×205pt → 360×151pt**였다. 높이는 약 26%, 면적은 약 30% 줄었다. WindowServer 창 상단은 전후 모두 y=46pt로 폴더 아래 배치를 유지했다. 실제 창 캡처에서 문구와 네 버튼이 잘리지 않는 것을 확인했다. 권한 안내나 오류가 있으면 내용에 맞춰 창이 커지는 구조는 유지한다.

## 측정 조건

- macOS 26.6.2 (25G83), 내장 화면 1개, 1800×1169pt.
- 비교 대상: 이번 최적화 전 백업 바이너리(`SHA-256 a0e4afb9…`)와 설정 간소화까지 포함한 최종 릴리스 바이너리(`e2fef7df…`). 소스 커밋 ID가 아니라 실행 파일의 해시다.
- 동일한 설치 경로와 로컬 개발 서명으로 한 버전씩 실행했다. 전후 designated requirement를 비교했고 서명 검증을 통과했다. 권한 토글이나 선택 설정 초기화는 하지 않았다.
- 설정·폴더 패널을 닫은 접힌 상태. 두 측정 직후 별도 AX 조회에서 선택 8개가 모두 화면 밖이고 임시 복귀 기록이 비어 있음을 확인했다.
- 각 버전 실행 후 15초 대기하고, `top`을 1초 간격으로 31회 실행했다. 최초 샘플은 제외해 버전당 30개를 비교했다. 실기 클릭·AX 반복 검사·빌드는 측정 중 실행하지 않았다.
- 다른 앱이 실행 중인 실제 사용 환경의 짧은 순차 측정이다. 무작위 순서의 반복 실험이나 고립된 전력 측정이 아니다.

재현 명령은 해당 버전만 실행한 뒤 PID를 대입한다. 이 명령 자체는 앱을 변경하지 않는다.

```sh
# 앱 실행 후 최소 15초 기다리고, 첫 데이터 행은 통계에서 제외한다.
/usr/bin/top -l 31 -s 1 -pid <FoldMenu_PID> -stats pid,cpu,mem,time
```

| 항목 | 최적화 전 | 최종 버전 |
| --- | ---: | ---: |
| CPU 평균 | 1.677% | 1.623% |
| CPU 중앙값 | 1.50% | 1.30% |
| CPU 범위 | 0.7–4.2% | 0.6–4.4% |
| CPU 95백분위 (nearest-rank) | 4.2% | 4.3% |
| 메모리 표시 범위 (`top MEM`) | 20–21M | 20–21M |
| 유효 샘플 수 | 30 | 30 |

CPU는 프로세스의 `top %CPU`이며 100%는 코어 하나에 해당한다. 메모리는 `top MEM`의 반올림된 footprint 표시이며 RSS·최대 힙·정확한 바이트 수와 동일하지 않다.

평균 차이는 약 0.05%p다. **유휴 CPU·메모리의 의미 있는 절감 효과는 이 측정으로 확인하지 못했다.** 이번 변경은 이동 검증 한 회차에서 원본·경계의 전체 창 목록 조회를 두 번에서 한 번으로 줄이는 것이며, 평상시 타이머 주기는 그대로다. 전체 CPU 50% 절감이나 배터리 수명 증가로 해석하지 않는다. 이동 중 CPU와 클릭 지연의 전후 비교, 장시간 메모리 증가, 전력 소비는 별도 측정하지 않았다.
