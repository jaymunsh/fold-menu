# 검증 기록

최종 문서 갱신: 2026-10-01. 동작 실측 환경: macOS 26.6.2 (25G83), Apple silicon. macOS 27은 미검증.

실기 확인은 **macOS 26에 한정**된다. 빌드 대상의 최소 OS 버전이나 정책 단위 검사 통과는 다른 macOS 버전에서의 동작 확인을 뜻하지 않는다. 현재는 완전 검증된 정식 배포본이 아니라 개발자 직접 빌드용 프로토타입이다.

각 절은 해당 날짜·빌드·실행 조건의 기록이다. 뒤의 보완 사항을 앞의 실행에도 소급해 적용하거나, 단위 검사·브랜드 자산 검사를 원본 메뉴 동작의 실기 검증으로 해석하지 않는다. 현재 구조와 미해결 사항은 [설계·개발 기록](project-history-and-architecture.md)에 요약했다. 이번 문서 갱신에서 새 잠금·절전·다중 모니터 메뉴 실기 검증은 수행하지 않았다.

## 초기 수정 원인 — 2026-09-22 15:25 KST

- macOS 26의 메뉴바 창은 Control Center가 호스팅한다. AppKit의 `windowNumber`를 UInt32로 강제 변환하거나 창 소유 PID가 Fold Menu라고 가정하면 충돌 또는 탐색 실패가 발생했다.
- 화면 밖 상태 아이콘은 `optionIncludingWindow`로 조회되지 않았다. 전체 창 목록에서 실제 창 번호를 찾도록 수정했다.
- 접힌 status item의 AppKit x 좌표는 이전 위치를 유지한다. 실제 WindowServer의 유일한 spacer 창 크기/행을 대조해 폴더 버튼을 250ms 간격으로 정렬한다. 좌표가 모호하거나 화면 밖이면 표시를 중단하고 복구한다.
- 이동 이벤트는 WindowServer 처리와 호스팅 프로세스 전달이 모두 필요했다. 전송 확인, 다른 창으로 전달되는 이벤트 차단, 짝이 맞는 mouse-up 정리, 원본/복귀 위치 검증을 추가했다.
- 메뉴가 아닌 일반 앱 창도 메뉴로 기다리던 로직을 수정했다. 대기를 45초로 제한하고 취소 및 복구를 UI에 노출했다.
- 취소/재실행 때 복귀 기준을 잃지 않도록 이웃 항목 ID를 저장하고 복귀 시 현재 좌표를 다시 찾는다.

## 당시 남은 검증 범위 — 2026-09-22

아래 항목은 첫 실행 시점의 범위다. 이후 일부 앱과 화면별 폴더 표시는 뒤 절에서 추가 확인했지만, 보조 모니터의 원본 메뉴 위치/포커스와 반복 잠금·절전 검증은 별도로 남아 있다.

- macOS 27, 전체 화면, 다중 디스플레이/해상도 변경, 노치 조합은 별도 실기 검증 필요.
- Orca, oMLX, Tailscale의 현재 버전은 이번 회귀 검사에 포함하지 않음.
- 정상 메뉴 대신 일반 앱 창을 여는 앱, 장시간/중첩 메뉴, 앱 종료와 클릭의 동시 발생은 추가 검사 필요.
- 메뉴바 아이콘은 마지막 캡처 이미지 또는 앱 아이콘이다. 숨겨진 상태의 실시간 그래픽 복제는 구현하지 않음.
- macOS의 비공개 이벤트 필드에 의존하는 메뉴바 재배치 특성상 후속 OS에서 재검증 필요.

## 포인터 및 동작 타이밍 — 2026-09-22 15:55 KST

이번 변경은 전체 펼치기나 편집 방식 변경이 아니라, 선택한 아이콘의 임시 이동/클릭/복귀 경로에 한정했다.

- 화면 밖 대상에 입력할 때 시스템 포인터가 왼쪽 화면 끝으로 제한되는 현상을 확인했다. `CursorTransaction`이 짧은 입력과 배치 안정화 동안 포인터 표시 및 장치 연결을 보호하고, 성공/오류 시 복원한다. 정상 실측 이동 약 300ms, 클릭 약 120ms. 네이티브 메뉴를 사용하는 동안은 보호를 해제한다.
- 좌표 기반 `mouseEventDeltaX/Y`에는 강제 이동 거리까지 섞였다. HID 입력의 `eventUnacceleratedPointerMovementX/Y`만 누적하도록 수정했다. 보호 중에는 일반 가속값 대신 원시 이동량을 적용하므로 평소와 이동 감도가 완전히 같지는 않다.
- 커서 표시/연결 정리는 중복 호출에 안전하며, 종료 처리와 4초 비상 복구도 둔다. 다중 디스플레이 제거 시 유효한 화면 안으로 복귀 위치를 제한한다. hide/show 및 연결 해제/복원 원칙은 [Apple Quartz 문서](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/QuartzDisplayServicesConceptual/Articles/MouseCursor.html)를 확인했다.
- 원격 상태 창이 눌림을 반영하기 전 고정 25ms 후 놓던 처리를, 실제 창 위치 변화 확인 후 놓도록 바꿨다. 이미 배치를 확인한 다음의 중복 대기 220ms는 40ms로 줄였다.
- Docker 복귀 실패를 추적한 결과 실제 AX x=-3924, WindowServer x=-3923으로 숨겨졌지만 `kCGWindowIsOnscreen`이 true로 남는 경우였다. 숨김 성공은 AX와 실제 창 **모두** 전체 화면 영역 밖인지로 판정한다. 일부만 화면에 걸친 아이콘은 성공으로 보지 않는다.

| --- | --- | --- | --- |
| HoldImg | 창 3102 관찰 | 0 / 0 pt | 없음 |

Docker 이동 주입은 시작점 (900,500)에 실제 입력 형태로 (24,12)를 더하고, (924,512) 복원을 검사했다. 별도로 사용자가 움직인 실행은 수치 비교 성공으로 세지 않고 INCOMPLETE로 구분했다. 중간 빌드에서 발생한 복귀 오판을 최종 성공 기록에 포함하지 않았다.

`scripts/verify-cursor.swift`는 실제 메뉴 창, 포인터 위치, 저장된 미복귀 정보를 함께 검사한다. 개발 검사는 포인터를 움직이고 메뉴를 열므로 사용자 작업과 동시에 실행하지 않는 것이 좋다. `bash scripts/test.sh` 전체 통과, release 빌드 및 codesign 검증 통과. macOS 27 및 장치별 연속 이동 감도는 여전히 별도 실기 검증 대상이다.

## 닫힌 폴더 + 개수 표시 — 2026-09-22

- 사용자 피드백에 따라 열린 폴더 시안을 폐기하고 닫힌 모양으로 고정했다. 0개도 `0`을 표시한다.
- 저장된 선택 ID와 현재 탐색한 항목 ID의 교집합을 세므로 종료한 앱은 표시 개수에서 빠지고, 일시적으로 꺼내 사용 중인 항목은 계속 포함한다. 임시 이동 로직은 이번 변경에서 수정하지 않았다.
- 26×20pt 템플릿 이미지를 네이티브 버튼과 접힌 상태의 오버레이가 공유한다. 숫자 변경으로 status item 너비나 경계 위치를 바꾸지 않는다. 툴팁/접근성 값과 패널 제목 옆에도 현재 개수를 제공한다.
- 0·1·4·12·99·100개 이미지 렌더 검사, 종료/선택 해제/중복 ID 계수 단위 검사 통과. 100개 이상은 작은 아이콘에서 `99+`, 툴팁은 실제 개수다.
- 실제 실행에서 폴더 버튼의 접근성 값 `폴더 항목 5개`와 패널의 Orca·Docker Desktop·HoldImg·donts3p·카카오톡 5개가 일치함을 확인했다. 0개 표시는 사용자 배치를 바꾸지 않고 렌더/단위 검사로 확인했다.
- 커서를 실제로 옮기는 기존 클릭 대행은 그대로다. 포인터 무이동 지원을 완료한 것으로 간주하지 않는다.
- 후속 디자인 조정: 상단 탭을 1.75pt 돌출로 낮추고 큰 이중 헤더를 없앴다. 본체 모서리는 2.25pt 반경, 테두리는 1.5→1.15pt로 줄였다. 검은 템플릿 색·26×20pt 캔버스·0 포함 숫자 규칙은 그대로다. 0/1/4/12/99/99+ 렌더 및 단위 검사 통과.

## 메뉴 열기 동작 단축 — 2026-09-22 16:25 KST

- 아이콘을 꺼낸 다음 별도로 커서를 움직여 클릭하던 단계에 `AXPress` 우선 경로를 추가했다. 액션 목록에 없거나 미지원 응답인 경우만 기존 포인터 클릭을 사용한다. `success`는 실제 메뉴 확인을 대신하지 않으며, 기존 창 관찰로 열림/닫힘을 검증한다.
- [Apple AXUIElementPerformAction 문서](https://developer.apple.com/documentation/applicationservices/1462091-axuielementperformaction?language=objc)에 따르면 모달 처리가 시작되면 `cannotComplete`여도 동작했을 수 있다. 이 응답에는 다시 클릭하지 않고 메뉴 관찰을 계속한다. 만료된 요소 오류도 임의 좌표 클릭으로 대체하지 않는다.
- 이동 후 50ms 간격 네 번의 목적지 판정을, 20ms 간격 세 번의 **동일한 AX 및 WindowServer 프레임** 확인으로 변경했다. 위치가 움직이거나 조회가 빠지면 연속 확인을 초기화한다. 대기 상한은 반복 횟수가 아닌 단조 시계 1.5초로 제한한다. 이후 중복 40ms 대기도 제거했다.
- 실제 메뉴 창: Docker 3462, HoldImg 3469, donts3p 3476, Orca 3497, 카카오톡 3504. 다섯 앱 모두 `native press requested` 경로로 열렸고 포인터 클릭 대체 경로는 실행되지 않았다. 다섯 항목 모두 다시 화면 밖으로 복귀하고 미복귀 정보가 비었다.
- 이동 입력 보호 시간(메뉴 사용 시간 제외): Docker 198/160ms, HoldImg 150/156ms, donts3p 154/153ms, Orca 153/156ms, 카카오톡 156/161ms (꺼내기/복귀). 이전 같은 세 앱 실측은 308~348ms였다.
- Docker·HoldImg·donts3p·카카오톡 포인터 최종 위치 검사는 열기/닫기 모두 0pt 오차. Orca는 사용자가 측정 중 움직여 수치 판정은 INCOMPLETE이며 메뉴 열림·복귀만 확인했다.
- 단위 검사는 미지원/모달 시간 초과/잘못된 요소 분기, 움직이는 창/누락된 프레임/잘못된 목적지의 안정화 초기화를 포함한다. 아이콘을 메뉴바로 임시 이동하는 방식은 그대로이며, 모든 모션 제거 또는 macOS 27 검증을 의미하지 않는다.

## 설정창 크기 정리 — 2026-09-22

- 고정 450×340pt 콘텐츠 프레임을 제거했다. 폭은 380pt, 높이는 내용의 고유 크기를 따르게 하고 NSHostingController의 최소/최대/선호 크기 추적을 켰다. 개수 표시는 제목 옆으로 옮겼다.
- 재실행 후 일반 상태 창 전체 크기 380×205pt를 실제 창 목록과 스크린샷으로 확인했다. 편집 시작·메뉴바 설정·종료·완료 버튼과 5개 표기가 모두 잘리지 않고 보였다. 비교하면 기존 창은 콘텐츠만 450×340pt였다.
- 기존 7개 단위 검사와 release 빌드/codesign 검증 통과. 이번 변경에서 아이콘 재배치 및 메뉴 클릭 경로는 수정하지 않았고, 사용자 배치를 바꾸는 편집/드래그 검사는 수행하지 않았다.

## 설정창을 폴더 아래에 배치 — 2026-09-22

- 설정창을 중앙에 띄우는 대신 현재 보이는 폴더의 오른쪽 끝에 맞추고, 메뉴바 아래 6pt 간격으로 연다. 화면 좌우 끝에서는 8pt 안쪽으로 제한한다. 시작 시 폴더 좌표가 아직 없으면 위치가 확인될 때 표시한다.

- 화면별 폴더 오버레이가 검정색 고정이라 비활성 모니터에서도 진하게 보이던 문제를 수정했다. `NSScreen.main`으로 키보드 포커스가 있는 화면을 찾고 비활성 화면의 폴더 그림만 낮은 불투명도로 표시한다. 버튼은 비활성화하지 않는다.
- 메뉴바 자동 숨김 중 status-host가 화면 위로 한 행 이동했을 때는 앵커 상실로 취급하지 않고 오버레이만 잠시 감춘다. 화면이 돌아오면 기존 접힘 상태를 유지한다.
- 잠금 복귀 후 실행 중인 선택 앱의 AX 항목이 검색에서 빠지면 접힘 검증을 보류한다. 상태창 안정화 지문에 x뿐 아니라 y·폭·높이를 포함했다. 오류 패널이 열린 상태라도 꺼낸 항목 복귀는 백그라운드에서 다시 시도한다.
- 250ms 오버레이 갱신에서 앵커와 화면별 슬롯을 동일한 WindowServer 창 목록 한 번으로 계산하도록 바꿨다. 재조회에 따른 불일치 가능성과 중복 호출을 줄인다.

## 화면별 폴더 아이콘 수직 정렬 — 2026-09-23

- 외부 화면의 30pt 메뉴바에 놓인 네이티브 폴더를 기준으로 모든 화면의 오버레이 높이를 30pt로 제한한 것이 원인이었다. 내장 화면의 실제 예약 슬롯은 39pt라 오버레이가 화면 위에서 9pt 내려간 `(1251, 9, 38, 30)`에 놓였고, 그림 중심도 주변 상태 아이콘보다 약 4.5pt 낮았다.
- 오버레이 버튼이 각 화면의 실제 예약 슬롯 높이를 채우도록 수정했다. 같은 장치에서 내장 화면 `(1251, 0, 38, 39)`, 외부 화면 `(1812, -1080, 38, 30)`으로 확인했고, 두 화면의 상단 캡처에서 주변 아이콘과 수직 정렬을 비교했다. 비활성 화면의 흐린 표시도 유지된다.
- 30pt 네이티브 앵커와 39pt 보조 슬롯을 함께 넣은 회귀 검사는 수정 전 실패, 수정 후 통과했다. 전체 `scripts/test.sh` 12개 그룹, 릴리스 빌드 및 앱 서명 검증 통과. 두 화면의 폴더를 눌러 패널 열기→다른 화면으로 이동→닫기를 확인했다. 선택된 실행 항목 5개는 모두 화면 밖이고 임시 복귀 기록은 비어 있다.

## 자동 항목 검색 비용 정리 — 2026-09-24

- 변경 전 실행 앱은 평상시 CPU 0~3%, 메모리 약 29MB였다. 전체 Accessibility 검색은 진단 실행에서 약 1.6초의 경과 시간이 들었다. 메뉴바 상태창 목록은 3초 간격 세 차례 조회에서 변하지 않았다. 따라서 250ms 폴더 위치 추적은 그대로 두고, 접힌 상태의 5초 주기 **전체 AX 검색만** 조건부로 줄였다.
- 상태창 ID·좌표·크기가 달라지면 다음 5초 타이머에서 검색한다. 변화가 없어도 마지막 검색 후 10초가 지나면 다음 타이머(최대 약 15초)에서 강제 검색하여 상태창에 드러나지 않는 AX 변경을 놓치지 않도록 한다. 창 목록을 읽지 못했거나 접근성 권한 상태를 다시 확인해야 하는 경우에도 검색을 건너뛰지 않는다. 설정·깨움 복구·꺼낸 항목 복귀에서 직접 요청하는 검색은 기존대로 실행한다.
- 테스트용 상태 아이콘을 잠깐 실행한 실기 검사에서 상태창 지문이 34개에서 36개로 변했고, 종료 후 WindowServer 정리가 끝나자 34개로 돌아왔다. 앱 재실행 후 두 화면 오버레이 각 1개, 네이티브 항목 1개, 선택 6개 중 실행 중인 5개 화면 밖, 폴더 개수 5, 임시 복귀 기록 없음이었다. 단위 검사는 최초 검색·동일 지문 생략·새 지문 즉시 검색·10초 경과 후 강제 검색·빈 지문·권한 변화·시간 역행을 포함한다.
- 이 변경은 안정된 메뉴바에서 전체 AX 검색 간격을 약 10~15초로 늘리는 정책이다. 실제 배터리 절감량은 별도 측정하지 않았고, macOS 27과 잠금·절전 복귀 반복도 이번에는 검증하지 않았다.

- 포인터 최종 오차, 전체 CPU·메모리·배터리 절감량, 다른 앱의 메뉴, 다중 화면의 실제 메뉴 클릭, 잠금·절전 반복과 macOS 27은 이번 검증에 포함하지 않았다. 전체 창 목록 조회 수 감소를 전체 CPU 사용량 50% 감소로 해석하지 않는다.

## 설정 간소화·유휴 측정·회귀 확인 — 2026-10-01

- 설정의 중복 제목과 큰 편집 박스를 제거했다. 편집 시작/완료 버튼과 항목 수를 한 줄로 묶고 정상 창 너비를 360pt로 줄였다. 메뉴바 설정·종료·완료, 권한 요청, 편집 중 수평 이동 안내와 제거 경고, 오류·취소·다시 접기 경로는 유지했다.
- 실제 AX 크기는 정상 상태 380×205pt → 360×151pt, 편집 중 360×229pt였다. 전후 정상 창 상단은 y=46pt로 폴더 아래를 유지했다. 정상/편집 캡처와 AX 트리에서 버튼 및 경고가 잘리지 않는 것을 확인했다. 편집 성공 안내나 오류가 있으면 정상 기준보다 높이가 늘어날 수 있다.
- 최적화 전 백업과 최종 버전을 같은 설치 경로·서명으로 순차 실행하고 각 15초 대기 후 30개 유휴 표본을 측정했다. CPU 평균 1.677% → 1.623%, `top MEM` 표시 20–21M → 20–21M이었다. 의미 있는 유휴 절감 효과는 확인하지 못했다. 조건·통계·원본 CPU 표본은 [설정 간소화·성능 측정](evidence/settings-and-performance-2026-10-01.md)에 기록했다. 배터리·이동 중 CPU·클릭 지연은 측정하지 않았다.
- `bash scripts/test.sh` 14개 그룹, 릴리스 빌드, 고정 로컬 개발 서명 및 `codesign --verify --deep --strict`가 통과했다. 새 UI를 현재 Mac의 앱 번들에 적용했다.
- `swift scripts/verify-folding.swift`에서 편집→접기 3회, 폴더→설정 다시 열기 3회가 통과했다. 이어진 60초 동안 112회 독립 AX 조회에서 8개 모두 화면 밖이고 선택 ID가 동일했다. 추가 편집 상태 캡처 후에도 완료로 접었다. 다른 앱 아이콘을 직접 드래그하지 않았다.
- 그 직후 donts3p 메뉴 검사는 `menuObserved=false`, `folderGap=nil`, `pendingReturn=false`로 **실패**했다. 폴더 UI에는 이동 결과 검증 실패 안내가 보였다. 별도 상태 조회에서 8개 항목 모두 기존 좌표로 접혀 있고 복귀 기록은 비어 있었다. 당시 추적 로그를 켜지 않아 이동 검증 실패의 구체적 원인은 확정하지 못했다.
- 같은 바이너리를 `--trace`로 다시 실행한 첫 시도는 `Cannot press donts3p`로 **INCOMPLETE** 종료했다. 뒤의 4회는 원본 메뉴 관찰, 폴더와 간격 0pt, Escape 이후 임시 복귀 기록 없음으로 모두 통과했다. 추적 로그에서도 꺼내기 검증→메뉴 창 관찰→닫힘→화면 밖 복귀가 확인됐다. 메뉴 내부 명령은 실행하지 않았다. 후속 성공으로 앞의 실패를 삭제하거나 간헐 실패가 해결됐다고 판단하지 않는다.
- 마지막에는 추적 실행을 정상 종료하고 일반 모드로 다시 실행했다. 최종 조회에서 선택 8개가 모두 기존 좌표로 접혀 있고 임시 복귀 기록은 비어 있었다. 네이티브 상태 항목 1개, 오버레이 `(1313, 0, 38, 39)` 1개, 폴더 패널 숨김을 확인했다. 문서 4개의 로컬 링크 48개·코드 펜스와 `git diff --check`도 통과했다. 다중 화면·잠금/절전 반복·macOS 27과 간헐 메뉴 이동 실패 원인은 남은 검증 범위다.

## 검색 내부 중복 계산·변경 발행·실패 진단 — 2026-10-01

- 기존 선택 8개에 PortManager가 추가된 9개 상태에서 진행했다. 검색 시작 때 기존 아이콘을 ID로 인덱싱하고 첫 일치 규칙을 유지한다. 화면 목록은 한 앱의 동기식 검색 안에서만 공유한다. 실제 AX 요소·좌표, 선택 ID, 추적/검색 타이머·이동 대기·복귀 정책은 유지했다. UI에서 쓰지 않는 검색 진행 상태와 동일한 권한 값의 변경 발행도 줄였다.
- 정상 메뉴 사용의 단계·경과 시간을 메모리에 최대 32개 남기고, 실패 때만 캐시의 `last-menu-failure.json` 하나를 덮어쓴다. 기록 실패는 복귀나 오류 안내를 바꾸지 않는다. 이벤트 전달·이동 검증·메뉴 관찰·복귀 단계와 겹친 느린 앱 검색을 구분한다. 추가 AX 조회·스크린샷·입력 내용·외부 전송은 없다.
- 검사 코드부터 작성하고 새 인덱스가 없는 상태에서 실패를 확인한 뒤 구현했다. `bash scripts/test.sh`는 최종 16개 그룹이 통과했다. 새 검사는 아이콘의 첫 일치·누락 fallback·다음 검색의 입력 변경, 제한된 단계 수·경과 시간, 실제 파일 저장·덮어쓰기·성공 후 파일 유지·저장 오류 이후 재사용을 확인한다.
- 읽기 전용 코드 리뷰에서 오류 문구의 AX 제목 유출 가능성과 진단만을 위한 추가 AX 조회가 지적됐다. 회귀 검사에 비공개 AX 문구와 실행 경로를 넣고, 기존 문자열 API에서 실패를 확인했다. 오류 종류만 저장하는 API와 실행 경로 가림으로 수정 후 검사·재리뷰를 통과했다. 사용자의 기존 오류 안내 문구는 유지한다.
- `swift build -c release`, 고정 개발 서명과 `codesign --verify --deep --strict`가 통과했다. 기존 화면 캡처 API의 deprecation 경고는 남았다. 정상 종료 후 현재 Mac에 적용했고, 권한 토글·선택 초기화는 하지 않았다.
