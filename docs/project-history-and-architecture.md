# Fold Menu: 설계·구현·문제 해결 기록

기록 기준: 2026-09-25. 이 문서는 초기 요구부터 현재 구현까지의 **의사결정과 기술적 이유**를 한곳에서 읽기 위한 요약이다. 실행별 좌표·창 번호·로그와 검증 범위는 [검증 기록](verification.md)과 [멀티모니터 실측](evidence/multi-monitor-2026-09-23.md)에 남긴다. 여기서 “구현”은 코드에 존재한다는 뜻이고, “실기 확인”은 명시된 OS·장치·앱에서 관찰했다는 뜻이다. 둘을 혼동하지 않는다.

## 1. 출발점과 목표

- 노치와 제한된 메뉴바 너비 때문에 가려지는 상태 아이콘을 하나의 **메뉴바 폴더**에 모으고, 폴더를 눌러 필요할 때 보는 앱을 원했다. 처음부터 사용자가 기대한 경험은 “아이콘 그림만 나열”이 아니라 **폴더 안에서 각 앱의 원래 메뉴를 사용할 수 있는 것**이었다.
- 대표 대상은 Orca, oMLX, Docker Desktop, Tailscale 등이었다. 이후 실기 검증에는 HoldImg, donts3p, 카카오톡 등도 포함됐다.
- 당시 개발 기기는 macOS 26.6.2였고, macOS 27에서도 계속 쓸 수 있도록 고려해 달라는 요구가 있었다. macOS 27 호환성이 이미 확인됐다는 뜻은 아니다.
- 앱 아이콘의 세부 디자인은 동작을 먼저 맞춘 뒤 조정하기로 했고, 최종적으로 메뉴바에는 숫자가 들어간 **닫힌 폴더 그림**을 사용했다.

초기 기대와 현재 구현의 차이가 핵심이다.

| 항목 | 초기 기대 | 현재 구현 |
| --- | --- | --- |
| 숨김 | 선택한 실제 상태 아이콘이 메뉴바에서 보이지 않음 | 사용자가 `⌘`-드래그로 폴더 왼쪽에 배치한 항목을, 길어진 Fold Menu 상태 항목의 화면 밖 영역에 둠 |
| 폴더 내용 | 원본 상태 아이콘이 폴더 안에 있는 듯 표시 | 마지막으로 읽은 상태 아이콘 이미지 또는 앱 아이콘을 **스냅샷**으로 표시. 실시간 복제는 아님 |
| 항목 사용 | 폴더 안에서 원본 메뉴를 즉시 사용 | 선택한 **실제 항목 하나**를 잠시 폴더 옆 메뉴바에 꺼냄 → 원본 메뉴 열기 → 닫힌 뒤 다시 숨김 |

| --- | --- |

| 방향 전환 | 사용자가 `⌘`-드래그로 직접 편집, 앱은 실제 배치를 읽어 접기만 수행 |
| 2026-09-22 | 원본 메뉴 임시 꺼내기/복귀 검증, 커서 보호·`AXPress`, 숫자 폴더 아이콘, 설정·앵커 조정 |
| 2026-09-23 | 잠금 복귀 안전장치, 화면별 폴더 오버레이, 비활성 색·수직 정렬 |
| 2026-09-24 | 상태창 변화 기반 검색 비용 조정, 두 화면·기존 선택 상태 재확인 |

## 2. 설계가 바뀐 이유

### 초기 자동 선택·이동 시도

초기 프로토타입은 접근성(Accessibility)으로 다른 앱의 메뉴바 항목을 검색하고, 설정 목록의 체크로 폴더에 넣거나 빼는 방식이었다. 이 방식에서는 “목록에 체크됨”, “폴더 패널에 앱 아이콘이 보임”, “원본 메뉴바 항목이 실제로 숨겨짐”이 서로 다른 상태였다. 사용자는 체크했는데 위에 그대로 보이거나, 다른 항목까지 함께 움직이거나, 간헐적으로 깜빡이는 상황을 겪었다. 설정 창이 과하게 컸고, 권한을 이미 허용했는데도 허용 요청이 다시 나타난 적도 있었다.

특히 메뉴바 항목을 아래 방향으로 드래그하면 macOS가 해당 항목을 메뉴바에서 제거할 수 있다. 이 과정에서 HoldImg가 보이지 않게 된 사건이 있었다. 당시 어떤 입력이 최종 제거를 일으켰는지 확정할 완전한 이벤트 기록은 없으므로, “앱 파일 자체가 삭제됐다”거나 “특정 코드 한 줄이 원인”이라고 단정하지 않는다. 다만 위험한 자동 재배치와 불명확한 안내가 문제를 키웠고, 이후 진단에서는 **원래 HoldImg 앱의 상태 항목이 다시 실행 중이며 화면 밖에 접혀 있는 것**을 확인했다. 당시 복원에 사용된 모든 수동 조치의 정확한 순서는 남아 있지 않다.

### 사용자 직접 편집으로 전환

안전성과 예측 가능성을 위해 **편집과 일상 사용을 분리**했다.

1. 설정에서 `항목 편집 시작`을 누르면 폴더를 펼쳐 실제 메뉴바 배치를 보여 준다.
2. 사용자가 `⌘` 키를 누른 채 아이콘을 **메뉴바 행 안에서 수평으로** 이동한다. 폴더 왼쪽은 접을 항목, 오른쪽은 계속 보일 항목이다.
3. `편집 완료하고 접기`에서 현재 배치를 다시 읽어 선택 ID를 저장한다. 체크박스가 다른 앱의 아이콘을 이동시키지 않는다.
4. 평소에는 폴더를 열고 대상 하나만 잠시 꺼내 사용한다.

`⌘`-드래그의 목적지는 반드시 메뉴바 행 안이다. 아래로 끌어 “폴더에 넣는” 제스처는 이 앱의 기능이 아니며, OS의 제거 동작과 충돌할 수 있다. 구현과 사용법은 [README](../README.md)에 적었다.

## 3. 현재 사용자 흐름

### 처음 실행과 권한

앱은 Dock 아이콘이 없는 메뉴바 앱(`LSUIElement`)이다. 다른 프로세스의 메뉴바 항목을 찾고 메뉴를 요청하는 데 손쉬운 사용 권한을 쓴다. 실제 상태 아이콘 이미지를 캡처하려면 화면 기록 권한이 필요하다. 이미지 캡처가 실패하면 기존 이미지·앱 아이콘·기본 기호로 대체한다. 권한이 없어도 임의로 다른 앱 항목을 재배치하지 않는다.

개발 빌드를 매번 임시 서명하면 macOS가 새 실행 파일을 이전에 허용한 앱과 다르게 취급할 수 있다. 재빌드 후 권한 팝업이 반복된 원인 후보 중 하나가 이 서명 신원 변화였고, 이를 줄이기 위해 `scripts/setup-signing.sh`의 **고정 로컬 개발 서명**을 사용한다. 개인 키와 키체인은 `.local-signing/`에 두며 공유·커밋하지 않는다. 실제 권한 상태는 `AXIsProcessTrusted()`로 다시 읽는다.

### 폴더 편집, 접기, 사용, 종료

```text
직접 편집: 편집 시작 → 사용자가 메뉴바 안에서 수평 이동 → 현재 배치 검색 → 선택 ID 저장 → 접기
일상 사용: 폴더 클릭 → 스냅샷 선택 → 실제 항목 하나 임시 이동 → 원본 메뉴 열기/닫기 → 원래 접힌 위치로 복귀
종료:     숨긴 영역을 먼저 펼침 → Fold Menu 종료
```

폴더 옆에 꺼낸 항목의 **실제 창**과 메뉴 창을 확인해야 성공으로 판정한다. 메뉴가 아닌 일반 앱 창을 연 경우도 고려하고, 대기가 끝나지 않으면 취소·복구할 수 있다. 복귀 기준은 일시적인 WindowServer 창 번호 대신 이웃 항목 ID로 저장해 재실행 후에도 다시 찾는다. 사용 중 앱을 강제 종료하는 경우까지 무조건 복구를 보장하지는 않는다.

### 화면 표시

- 메뉴바에서 보이는 Fold Menu는 닫힌 폴더 모양이며 내부에 현재 검색된 선택 항목 수를 그린다. 0개는 `0`, 100개 이상은 `99+`로 표시한다. 고정 이미지 크기를 유지해 숫자 변화가 메뉴바 배치를 밀지 않게 한다.
- 폴더 패널은 메뉴바 버튼 바로 아래에 붙고, 설정 창도 버튼 아래에 배치한다. 초기 설정 창의 지나친 높이와 화면 중간 배치를 줄였다.
- 항목 그림은 실시간 미러링이 아니다. 메뉴바 항목의 CPU·네트워크 수치나 배지 등이 계속 변해도 폴더 패널의 그림은 이전 캡처일 수 있다.
- 메뉴바에서 항목을 꺼낼 때 보이는 이동은 실제 원본 상태 아이콘의 재배치다. 포인터 자동 입력을 줄이고 그림을 다듬었지만, 이 OS 수준 이동 자체를 단순 SwiftUI 애니메이션처럼 없앨 수는 없다.

프로젝트는 Swift Package의 macOS 실행 타깃으로 구성된다. `scripts/build.sh`가 release 바이너리를 `dist/Fold Menu.app`에 넣고 서명·검증한다. Package의 최소 타깃은 macOS 14지만, **실제 동작 검증은 주로 macOS 26.6.2**에서 이루어졌다. 최소 빌드 타깃과 기능 호환성은 다른 주장이다.

### 접는 방식과 안전 경계

접을 때 Fold Menu의 **네이티브 상태 항목 하나**를 길이 10,000pt의 예약 영역으로 만든다. 사용자가 그 왼쪽에 놓은 다른 앱 아이콘은 화면 밖 좌표에 위치한다. Fold Menu의 작은 폴더 그림은 확인된 실제 예약 영역 끝에 오버레이한다. 따라서 다른 앱 항목을 가짜로 복제해 숨기는 구조가 아니며, 다른 앱에 아이콘 이동 API를 제공하는 것도 아니다.

AppKit이 보고하는 상태 항목 프레임은 접힌 직후 예전 38pt 폭으로 남을 수 있다. macOS 26에서는 메뉴바 창이 Control Center에 호스팅되기도 한다. 그래서 앱 PID나 AppKit `windowNumber`만 신뢰하지 않고, 실제 WindowServer 상태창의 ID·PID·좌표를 확인한다. 추적한 경계 창이 재생성되면 **유일하게 일치하는 후보**만 채택한다. 후보가 없거나 모호하면 다른 항목을 덮지 않기 위해 오버레이를 감추며, 평상시 2초간 계속 경계를 잃으면 안전하게 펼친다. 이때 사용자가 `다시 접기`로 재시도할 수 있다.

### 원본 메뉴 열기와 복귀

숨긴 항목은 접근성 요소와 WindowServer 창 양쪽에서 확인한 뒤 이동한다. 임시 슬롯은 AX 글리프 x가 아니라 **폴더 경계에 실제로 붙은 상태창 호스트**를 기준으로 고른다. 입력은 메뉴바 행 안에서만 보내며, 이벤트가 다른 창으로 전달되려 하면 중단한다. 원본 호스트가 움직이기 시작했는지 본 뒤 mouse-up을 보내고, AX 프레임과 실제 호스트 프레임이 목적지에서 연속으로 안정됐을 때만 성공한다. 화면 밖으로 돌아갈 때도 `kCGWindowIsOnscreen` 하나에 의존하지 않고 양쪽 프레임이 모두 실제 화면 밖인지 확인한다.

임시 배치 기록(`temporaryPlacements.v1`)은 메뉴가 열린 동안과 재실행 후 복구를 위한 것이다. 메뉴가 닫히면 원래 이웃 또는 폴더 경계를 다시 찾아 복귀한다. 실패하면 기록을 함부로 지우지 않고, 조건이 안전할 때 재시도하거나 사용자에게 복구 버튼을 보여 준다. 앱 종료 시에는 접힌 영역을 먼저 펼친다.

### 두 모니터와 잠금 복귀

두 번째 네이티브 `NSStatusItem`을 만들지 않는다. 접힌 상태의 **각 디스플레이에 클릭용 오버레이 하나**를 두고, 하나의 공용 폴더 패널을 눌린 화면의 폴더 아래로 옮긴다. 화면별 실제 메뉴바 높이(실측 39pt와 30pt)를 사용해 수직 정렬한다. 활성 화면의 폴더 그림은 진하게, 비활성 화면은 옅게 표시한다. 화면 슬롯이 다른 프로세스 소유이거나 유일하지 않으면 그 화면의 오버레이를 생략한다.

기기·화면 깨움, 세션 재활성화, 화면 구성 변경 알림 뒤에는 WindowServer 창의 ID·좌표·크기가 안정될 때까지 기다린다. 잠금 직후 창이 재생성되는 동안 잘못 펼치지 않도록 앵커 상실의 안전 펼침을 12초 유예한다. 실제로 선택 항목이 다시 노출됐다고 확인할 때만 접기를 다시 적용하고, 연속 재시도를 제한한다. 실행 중인 선택 앱의 AX 항목이 일시적으로 누락되면 성공이나 실패로 단정하지 않고 판정을 보류한다.

### 검색 주기와 성능

화면별 폴더 위치는 250ms마다 확인한다. 이 추적은 메뉴바 배치 변화에 따라 버튼이 다른 아이콘을 덮지 않도록 하는 경로라 유지했다. 전체 Accessibility 항목 검색은 매번 무조건 실행하지 않는다. 5초마다 상태창 ID·위치·크기 지문을 비교하여 변화가 있으면 검색하고, 변화가 없어도 마지막 검색 후 10초가 지난 다음 검사(대략 10~15초 간격)에서 다시 검색한다. 권한 상태가 바뀌었거나 창 목록이 비면 검색을 건너뛰지 않는다. 설정·깨움 복구·꺼낸 항목의 복귀 검색은 별도로 유지한다.

변경 전 실측은 평상시 CPU 0~3%, 메모리 약 29MB, 진단용 전체 AX 검색 경과 시간 약 1.6초였다. 검색 정책 변경 후 **배터리 절감량을 따로 실측하지는 않았다**. 수치를 근거 없이 “최적화 완료”로 해석하지 않는다.

## 6. 검증 방법과 확인된 범위

자동 정책 검사는 `bash scripts/test.sh`, 릴리스 빌드·서명 검사는 `bash scripts/build.sh`로 실행한다. AX 검색과 메뉴바·화면별 실제 좌표는 `scripts/diagnose-fold-state.swift`, `scripts/verify-mirrors.swift` 등으로 **별도 관찰**했다. 테스트 도구의 `AXPress` 성공 응답만으로 실제 앱 메뉴가 열렸다고 인정하지 않고, 팝업 창과 복귀 위치를 함께 봤다. 메뉴 클릭을 시험할 때는 다른 앱의 메뉴 명령을 실행하지 않고 Escape로 닫았다.

- macOS 26.6.2에서 Docker Desktop, HoldImg, donts3p, Orca, 카카오톡의 원본 메뉴 열림·닫힘과 항목 복귀를 확인한 기록이 있다. 각 실행의 범위와 예외는 [검증 기록](verification.md)을 따른다.
- 내장 화면과 외부 화면의 폴더 버튼 각 하나, 네이티브 상태 항목 하나, 패널의 화면 간 열기·이동·닫기 및 수직 정렬을 확인했다. [실측 기록](evidence/multi-monitor-2026-09-23.md)은 당시 창 좌표와 명령 출력을 보존한다.
- 마지막 검색 비용 변경 후에는 선택 ID 6개 중 **그때 실행 중이던 5개**가 화면 밖에 있고, 미복귀 임시 항목이 없음을 확인했다. ‘선택 6개’와 ‘그 순간 표시되는 개수 5개’는 모순이 아니다. 종료된 앱 ID는 설정에 남아도 현재 개수에서 제외한다.
- 실제 잠금/절전의 장시간 반복, 물리적 모니터 분리·재연결, 노치·전체 화면 조합, macOS 27 및 모든 앱 버전의 동작까지 포괄한 검증은 없다.

`scripts/verify-cursor.swift`와 일부 `--physical` 도구는 실제 포인터와 다른 앱 메뉴를 움직인다. 사용자가 작업 중인 화면에서 무작정 돌리지 않는다. 테스트 전에는 저장된 선택·미복귀 기록을 읽고, 후에는 실제 항목 위치와 `temporaryPlacements.v1`을 다시 확인한다.

## 7. 남은 제약과 다음 검증 과제

1. **보조 모니터 원본 메뉴 위치/포커스:** 보조 화면 폴더는 표시되지만 그 화면을 키보드 포커스 화면으로 만들지 않는다. 원본 상태 항목을 클릭한 화면으로 안전하게 임시 이동할 수 있는지, 테스트 항목으로 먼저 검증해야 한다. 현재 코드를 단순 색상 변경만 해서는 사용자 기대를 충족하지 못한다.
2. **macOS 27 호환성:** 핵심 재배치는 공개된 “다른 앱의 상태 항목을 폴더로 옮기는 API”가 아니라 WindowServer 상태창과 비공개 이벤트 필드에 의존한다. macOS 업데이트마다 실제 메뉴 열림·복귀·잠금 복귀를 확인해야 한다. `CGWindowListCreateImage`는 macOS 14부터 deprecated 경고가 있으며 ScreenCaptureKit 전환도 별도 검토 대상이다.
3. **앱별 차이:** AX 메뉴바 자식을 노출하지 않는 앱은 목록에 나타나지 않을 수 있다. 일부 앱은 팝업 대신 자체 창을 열고, 상태 아이콘이 동적으로 추가·제거되며, 메뉴 사용 중 앱이 종료될 수도 있다. 모든 앱에 동일한 클릭/복귀를 보장하지 않는다.
4. **시각적 정확도:** 접힌 동안 상태 그림을 실시간 스트리밍하지 않는다. 배지·측정값의 즉시 동기화가 필요하면 별도의 캡처/갱신 설계가 필요하다.
5. **권한과 배포:** 로컬 개발 서명으로 재빌드 신원 문제를 줄였지만 배포용 서명·공증·업데이트·권한 재승인 경험은 별도 설계/검증 대상이다.

## 8. 운영·유지보수 원칙

- 다른 앱 아이콘을 자동으로 묶어 이동하거나, 확인되지 않은 위치에서 계속 입력을 재시도하지 않는다. **호스트 ID·PID·위치·행이 모호하면 중단**한다.
- 메뉴바 항목이 사라졌다고 앱 파일이 삭제됐다고 단정하지 않는다. 원본 앱 실행 상태, 자체 메뉴바 표시 설정, macOS 메뉴바 상태, AX와 WindowServer 프레임을 각각 확인한다.
- 테스트/문서에서는 “코드에 있음”, “단위 검사 통과”, “실기에서 확인”, “사용자 보고”, “추정 원인”을 분리해 쓴다.
- 회귀 시에는 선택 ID와 미복귀 기록을 먼저 읽고, 재빌드 후 권한 신원이 유지되는지 확인한다. 테스트가 사용자의 실제 배치를 바꿨다면 확인 없이 성공으로 보고하지 않는다.
- 세부 현상과 수정 당시의 좌표·로그는 이 요약을 반복 확장하기보다 [검증 기록](verification.md)에 추가하고, 이 문서의 현재 상태/미해결 목록만 갱신한다.
